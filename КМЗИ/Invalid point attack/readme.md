Invalid Point атака на некорректную реализацию ECIES.
Доп. источник: 
Antipa A. et al. Validation of elliptic curve public keys //International workshop on public key cryptography. – Springer, Berlin, Heidelberg, 2003. – С. 211-223.

Студенту дается адрес сервера - 45.132.17.192:8080, на котором запущен алгоритм шифрования ECIES на основе эллиптических кривых.
Задача - вскрыть закрытый ключ сервера, используя недостаток в реализации, связанный с отсутствием проверки принадлежности точки кривой в процедуре расшифрования.

На сервере запущено Flask-приложение.
При запросе /info высылаются параметры используемой для зашифрования и расшифрования данных:
- в качестве симметричного шифра SYM используется AES в режиме CTR;
- для вычисления тега MAC используется HMAC-SHA256;
- KDF: для извлечения ключей симметричного шифра и HMAC используется хэш-функция SHA512 (первые 256 бит – ключ AES, остальные 256 бит – ключ HMAC).

Для получения шифртекста произвольного сообщения необходимо использовать метод /encrypt, где в форме запроса нужно указать файл.
В результате возвращается шифртекст сообщения в следующем виде:
- 65 байтов: 0x04 || 32 байта x-координаты точки R || 32 байта y-координаты точки R;
- 32 байта тега t, вычисленного как HMAC-SHA256 от оставшихся данных (префикс для AES256-CTR || зашифрованные данные);
- оставшиеся данные: 8 байт префикса || шифртекст c сообщения , полученного с помощью AES256 в режиме CTR.
Для расшифрования необходимо использовать метод /decrypt.
Известно, что значение закрытого ключа не превышает 1000000000000000000000000000000000000.
